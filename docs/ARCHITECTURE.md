# Design and trust boundaries

The browser posts a single question (3–1200 characters) to `/api/ask`. It renders responses through `textContent`, not HTML. There is no conversation history, database of users, analytics, or browser storage.

The server validates the request with Pydantic (`extra='forbid'`), then starts a fresh agent. `OpenAI()` reads environment configuration from `.env` or the shell; the model is fixed to `gemma-4-E4B-it`, temperature 0, max 1200 output tokens per request, no SDK retries. The configured base URL must use HTTPS at `llm.nat-d.uk`. Client timeouts are 25 seconds per model request. A 65-second budget is checked between rounds; it is not a hard cancellation of an in-flight request, so the worst case is approximately 90 seconds.

The first model call must request `search_knowledge`. Subsequent calls may search again, read a previously retrieved article through `get_article`, or return an answer. There are at most four model rounds and six tool calls, including a possible JSON-format repair. Unknown tools, malformed arguments, extra fields, and arbitrary article IDs stop the request with a safe error. This application never gives the model an operating-system or network tool.

The class proxy was observed returning a Gemma-native single-field argument wrapper rather than JSON on the first call. `tool_arguments.py` supports exactly the observed wrapper via a full-match regular expression, verifies the tool name and corresponding field, and then applies the normal Pydantic schema. Extra fields or trailing bytes fail. Validated arguments are sent back to the proxy as standard JSON in the assistant tool-call history. Standard JSON calls still work. This compatibility rule is not a general repair or code interpreter.

Retrieval tokenizes English words, removes common stop words, and computes BM25 plus a normalized sparse TF-IDF cosine similarity. A fixed domain glossary expands recognized phrases. Hybrid score = 0.65 × cosine + 0.35 × BM25/(BM25+5). Return up to three articles with score **strictly greater** than 0.30. The vectors and article lookup form a tiny in-memory index rebuilt on startup. Each article is one retrieval unit; no overlapping chunks are needed for these short entries.

If a model rewrite retrieves nothing, the dispatcher tries the original question with the same cutoff. The trace records both searches. If there is still no evidence, the application returns a deterministic “I don't know” abstention. Otherwise the model must produce a Pydantic-valid answer with a status, plain text, and citation IDs. A single surrounding JSON code fence is accepted. One invalid answer may be returned for schema correction within the same four-round budget; a second invalid answer fails. Citations must refer to evidence actually retrieved during this request. A model may choose to abstain despite having retrieved evidence.

The tool output is marked as fictional data. The system prompt says that tool text and user text cannot override policy. This helps with prompt injection, but is not a proof against it. The stronger boundary is capability restriction: there is no secret-reading, write, or remote-action capability to dispatch. The live injection example was blocked as an invalid call and did not produce a useful Wi-Fi answer; the project records this as a functional failure, not a flawless safety success.

Endpoints: `GET /` interface; `GET /api/health` non-secret configuration status; `GET /api/articles` public fictional corpus; `POST /api/ask` model-backed lookup; `GET /openapi.json` API schema. No browser CORS allow-all policy is added. Content Security Policy permits self-hosted assets only, API responses are marked no-store, and exceptions do not disclose upstream response bodies. This local prototype has no authentication or quota guard for internet deployment.

The offline evaluation ranks the fixed original question directly; it isolates retrieval and never calls the model. Live smoke tests cover the loop and reference IDs but are development diagnostics. Neither establishes semantic answer faithfulness or real-user performance.
